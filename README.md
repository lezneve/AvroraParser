# AvroraParser

пошук товарів і знижок у магазинах «аврора», з термінала.

невеликий python-скрипт: вибираєш магазин, шукаєш товар за штрихкодом або скануєш знижки. окремий скрипт синхронізує каталог «аврори» з postgresql. скрипти ходять у мережу (api цінників і сайт «аврори»): без цього вони не працюють.

лише код, без релізів. MIT.

## запуск

потрібні python 3.12 або новіший і [uv](https://docs.astral.sh/uv/). запускати з кореня репозиторію.

```sh
uv sync
uv run avrora_parser.py
```

## меню

| пункт | що робить |
| --- | --- |
| 1 | пошук товару за штрихкодом: ціна, знижка, артикул, залишок, kt |
| 2 | сканування знижок у вибраному магазині |
| 3 | змінити магазин (за містом) |
| 4 | змінити kt-фільтр |
| 0 | вихід |

під час першого запуску скрипт просить вибрати місто й магазин. kt вводяться через кому, `all` означає всі категорії. товар із нульовим залишком, який позначено на сайті «тільки на сайті», так і показується.

сканування перебирає штрихкоди від 1 до 150000 у 15 потоків і показує один рядок прогресу. у таблицю потрапляють товари зі знижкою, залишком від 1 і потрібним kt; наприкінці показуються 20 найбільших знижок. запити, на які після трьох спроб немає відповіді, перелічуються в підсумку. колір вимикається змінною `NO_COLOR` і сам вимикається, коли вивід не в термінал.

## синхронізація каталогів

| команда | що робить |
| --- | --- |
| `uv run dumper_avrora.py` | товари й ціни «аврори» в таблицю `products`, зображення в avif у cloudflare r2 |

`dumper_avrora.py` питає: повний перебір з першого штрихкоду або продовження з місця, де зупинився (за товарами, перевіреними за останні 24 години). магазин у ньому зашитий у коді (`SHOP_NUMBER = "988"`), `config.json` він не читає. режиму без зображень немає: потрібні всі змінні r2.

таблиці створюються самі.

## структура

| файл | що в ньому |
| --- | --- |
| `avrora_parser.py` | меню, пошук, вивід |
| `avrora_api.py` | запити до api, моделі магазину й товару, сканування |
| `common.py` | конфіг, запити з повтором, рядок прогресу, таблиця |
| `dumper_avrora.py` | синхронізація «аврори» з postgresql і r2 |
| `pyproject.toml`, `uv.lock` | залежності для uv |

## налаштування

`config.json` створюється сам після вибору магазину: місто, номер і назва магазину, kt-фільтр. він локальний і в репозиторій не входить.

для синхронізації потрібен локальний файл `.env` (теж не в репозиторії):

| змінна | значення |
| --- | --- |
| `DATABASE_URL` | рядок підключення до postgresql |
| `R2_ACCESS_KEY`, `R2_SECRET_KEY` | ключі доступу до cloudflare r2 |
| `R2_ENDPOINT`, `R2_BUCKET` | s3-сумісна адреса r2 і назва бакета |
| `CDN_URL` | публічна базова адреса зображень |


## обмеження

не перевірено, тому не обіцяється:

- що api цінників і сайт «аврори» відповідають так само, як тоді, коли писався код. скрипт залежить від їхніх адрес і формату відповіді; коли вони зміняться, він перестане працювати
- позначка «тільки на сайті» береться з розмітки сторінки пошуку; якщо розмітка зміниться, позначка просто не знайдеться
- повний дамп у postgresql і завантаження зображень у r2
- автоматичних тестів немає

відомо:

- сканування робить до 150000 запитів до api; між ними немає пауз, лише обмеження в 15 потоків
